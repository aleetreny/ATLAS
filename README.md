# ATLAS

### Algorithmic Techniques for Learning And Statistics

**Read it as a website: [aleetreny.github.io/ATLAS](https://aleetreny.github.io/ATLAS/)**

ATLAS is an atlas of visual, interactive explanations of machine learning: from drawing straight lines through point clouds to modern generative models, causal inference, reinforcement learning and the engineering toolkit around all of it. Every article builds the method from scratch, breaks it on purpose, runs it live in your browser, and tells you exactly when to reach for it. The aesthetic follows [MLU-Explain](https://mlu-explain.github.io/).

Every branch of the map is complete. The front page is the index: eight modules, each with its own gallery and a full branch map of the techniques it covers.

## The eight modules

1. **Supervised Inference**: regression, classification and computer vision, from OLS to segmentation and neural rendering.
2. **Unsupervised Structure Discovery**: clustering, dimensionality reduction, anomaly detection and association rules.
3. **Generative AI**: GANs, VAEs, flows, energy models and the diffusion family, measured against exact likelihoods wherever one exists.
4. **Sequential Intelligence**: language from TF-IDF to attention and state-space models, time series from ARIMA to zero-shot forecasting, and audio.
5. **Agents & Strategy**: optimization, bandits and reinforcement learning, where the data is generated by the decisions themselves.
6. **Relational Intelligence**: recommenders and graphs, where an object is defined by its relations instead of its features.
7. **Causality, Uncertainty & Explanation**: confounding, instruments, do-calculus, conformal prediction, Bayesian posteriors, SHAP and saliency.
8. **The Engineering Toolkit**: tuning, AutoML, transfer, LoRA, validation, metrics and vector search, run across the atlas's own datasets.

## The rules the site is built on

- **Every figure is measured, never quoted.** Each number on a page comes out of a generator in `src/utils/generate_*.py` that actually runs the experiment, with seeds, controls and caching. When a measurement contradicts the intended storyline, the storyline is rewritten around the measurement.
- **The prose is composed from the data at load time.** Each article's `js/prose.js` writes every numeric sentence from the article's JSON, with a branch on every comparison, so re-running a generator moves the text with the result instead of leaving it quietly wrong.
- **Pages check themselves.** Articles ship load-time guards that recompute reference quantities in the browser and compare them against what the generator measured, and a repository-wide guard (`src/utils/check_publication.py`) keeps the front page, the state table and the article chain coherent on every push.

## How it works

A static site served from the repository root by GitHub Pages: hand-written HTML, ES modules, D3 v7 and KaTeX vendored in `assets/js/vendor/`. No frameworks, no build step, no npm. Scrollytelling runs on a small `IntersectionObserver` helper, and shared chart helpers live in `assets/js/`.

To browse locally, serve the repository root with any static server and open the front page:

```
python -m http.server 8737
```

To reproduce an article's figures, run its generator (for example `python src/utils/generate_gnn_data.py`). Heavy datasets are downloaded on first use to `~/.atlas_vision_data/`, outside the repository, and each finished experiment is cached there so an interruption never costs the whole run. Exact reproduction is per machine: thread counts change the order of floating-point reductions, so the fifth decimal can move between machines, and wall-clock times are published only as ratios between arms of the same experiment.

## Repository layout

- One folder per article at the root (`classical-regression/`, `gnn/`, ...), each with its `index.html`, `js/`, and `data/` JSON.
- `assets/`: shared styles, fonts, chart helpers, vendored libraries and the front-page thumbnails.
- `src/utils/`: the generators that measure every published figure, plus the publication guard.
- `src/models/`: from-scratch NumPy implementations that several generators and articles use as their honest baseline.
- `datasets/`: the small CSVs a few generators read; everything heavy lives outside the repository.
- `docs/`: working documentation, in Spanish: how the repository is worked on, the article recipe, the verification playbook, the deployment procedure and the project state.
