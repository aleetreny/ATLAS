Module 2.4 · Association Rules · Bought Together

Every other article in this module works on points: rows of numbers, with distances between them and a middle somewhere. Change the object and all of that goes away. A basket is a set. Two baskets have no distance between them, there is nothing to average, and there is no direction to project along. The only operation available is counting how often things happen together.


Counting is the easy part.


Two algorithms make that tractable, and they do it in two completely different ways. Apriori prunes: it never counts a set that it can already prove is not worth counting. FP-Growth compresses: it puts the whole database into a tree small enough to mine directly. Neither is clever about shopping. Both are clever about subsets.


Both run in this page and are checked at load time against the references the generator produced.

Counting Is The Easy Part

The support of a set is how many baskets contain all of it. One pass over the database gives every one of these numbers.

The Lattice

Join each set to the sets one item larger that contain it, and the subsets become a structure rather than a list.

A Threshold

Call a set frequent when its support reaches some minimum. Filled is frequent; hollow is not.

The Whole Trick

A set can only be frequent if every one of its subsets is, so everything above an infrequent set can be discarded without ever being counted.

Counted, And Never Counted

Downward closure is one line and it is the entire algorithm:

$$A \subseteq B \implies \mathrm{supp}(A) \ge \mathrm{supp}(B)$$

A basket that contains B contains A as well, so A cannot be rarer. Turned around: if A is not frequent, nothing containing A can be.

The Other Trick

Apriori attacks the number of candidates. FP-Growth attacks the database.


Sort each basket's items into one fixed order and insert it into a prefix tree: baskets that begin the same way share the same nodes, and a count on each node is all that survives of them. Mine the tree and you never touch the transactions again. The ordering is not a detail of the implementation. It is the algorithm, and the buttons below say why.

Confidence Is A Trap

A frequent set is not a rule. A rule points somewhere.


Three numbers describe one, and only two of them are ever quoted:

$$\mathrm{conf}(A \Rightarrow B) = \frac{\mathrm{supp}(A \cup B)}{\mathrm{supp}(A)}, \qquad \mathrm{lift}(A \Rightarrow B) = \frac{\mathrm{conf}(A \Rightarrow B)}{\mathrm{supp}(B)}$$

Confidence is how often B follows A. Lift is how that compares with how often B happens anyway, and it is the one that can be below one.

The Verdict

Two algorithms, three measures, and one question to ask before believing any of it.

Reach for When What it buys Watch out for
Apriori Sparse baskets, a threshold you are willing to defend, and you want to see the work Measured above. The threshold.
FP-Growth The same problem, larger, and the database fits in memory once compressed Measured above. The ordering, and the tree itself.
Confidence You already know the conclusion is rare Measured above. Common consequents.
Lift You want to know whether the antecedent tells you anything at all Measured above. It is symmetric.
