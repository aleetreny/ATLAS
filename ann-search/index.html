Finding the nearest vectors exactly means looking at all of them. Three ways of not doing that, each scored against the exact answer, with the cost counted in distances rather than in seconds

Module 8.3 · Vector Search · ANN, HNSW and FAISS

The neighbour embedding article already searched for nearest neighbours, and it searched exhaustively: compute every distance, sort, keep the closest. That is the correct algorithm and it never stops being correct. It stops being affordable, and the point at which it does is not "when there are a lot of vectors" but a number, which this page measures.


Everything here is counted in distance evaluations rather than in seconds. A wall clock measures whatever else the machine was doing, and it does not survive being read anywhere else; the number of distances an index computes to answer a query is a property of the index and the data. The indexes are written in the generator with the counter inside them, so the figures are what each one actually paid.
